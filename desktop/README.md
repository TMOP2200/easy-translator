# Easy Translator · 桌面伴生

把「鼠标停在英文上约 5 秒 → 弹出中文释义」从浏览器**扩展到整台电脑**：
记事本、Word、微信、VS Code、PDF 阅读器……任何应用里的英文都能查。
UI 与浏览器扩展同一套设计语言：**白底气泡 + 藏青描边 + 右下角的吉祥物**，
所有释义都装在她的对话气泡里。

## 一步步来（从零开始）

### ① 先把代码放到电脑上

```powershell
cd ~
git clone https://github.com/Fishman-free/easy-translator.git
```

没有 git 也行：在 GitHub 页面点 **Code → Download ZIP**，解压到任意目录。

下面命令里的 `<项目目录>` 都指**你放这份代码的文件夹**，本机示例：

```
C:\Users\21560\Desktop\Easy-translator
```

### ② 启动

**推荐用绝对路径**——不管你现在在哪个目录都能跑对（最不容易出错）：

```powershell
powershell -ExecutionPolicy Bypass -File "<项目目录>\desktop\run.ps1"
```

或者先切进项目目录、再用相对路径：

```powershell
cd "<项目目录>"
powershell -ExecutionPolicy Bypass -File .\desktop\run.ps1
```

首次运行会自动建 `.venv` 并装依赖（Pillow / uiautomation / comtypes），约需一两分钟；
跑完会打开**控制窗口**（顶部一颗「开 / 关翻译」大按钮）并开始监听鼠标。

> ### ⚠️ 最常见的坑（真实案例，一定要看）
>
> ```text
> PS C:\Users\21560> cd ~/desktop
> PS C:\Users\21560\desktop> powershell -ExecutionPolicy Bypass -File desktop\run.ps1
> -File 形式参数的实际参数"desktop\run.ps1"不存在。请提供现有".ps1"文件的路径……
> ```
>
> **原因**：`~/desktop` 是 **Windows 桌面**（`C:\Users\21560\Desktop`），**不是**项目里的
> `desktop` 子目录。此时 `desktop\run.ps1` 被拼成 `C:\Users\21560\Desktop\desktop\run.ps1`
> —— 那儿当然没有这个文件。
>
> **记住两件事**：
> 1. **`Desktop`（大写，你的桌面）≠ 项目里的 `desktop`（小写，子目录）**，别混；
> 2. 直接用 ② 的**绝对路径**写法，无论当前在哪个目录都不会错。

其它两种启动方式：

```powershell
powershell -ExecutionPolicy Bypass -File "<项目目录>\desktop\run.ps1" --settings  # 只改设置、不监听
powershell -ExecutionPolicy Bypass -File "<项目目录>\desktop\run.ps1" --selftest  # 只跑自检后退出
```

### ③ 界面（第一次用建议做这三件事）

启动后弹出的**控制窗口就是这个程序的主界面**：**左侧深色导航**（总览 / 通用 / 本地小模型 / 图片取词 / **装饰图** / 数据 / **使用说明**，
**点哪个栏目就只显示哪个栏目**）+ **顶部标题栏**（右边显示当前是「已启用 / 已暂停」）+ **中间卡片** + **底部状态栏**
（左边一个圆点 + 状态，右边显示当前用哪个文本/视觉模型）。
**窗口可以随意拉大拉小**：说明文字的折行宽度和卡片顶上的图都会跟着重算，窄窗口里不会被切掉右边。

| 卡片 | 第一次要做什么 |
|---|---|

「文本模型 / 视觉模型」两个**下拉框**（也能直接手打），选完点「测试文本查词」当场验证。机器上还没有模型时，用这一栏的「**下载所选模型**」由 Ollama **从官方库**（正版、免费）一键下载，另有「打开官方模型库 / 先装 Ollama」两个官方入口；模型文件（约 1~3 GB/个）由 Ollama 管理，本程序不下载、不代理任何模型文件 |
| **图片取词** | *可选*。给图片/游戏这类取不到文字的地方用；需要本地视觉模型在跑（没配就静默，不会乱弹） |

| **数据** | 看配置存在哪：`%APPDATA%\EasyTranslator\config.json`；「恢复默认设置」一键回出厂 |
| **使用说明** | **内置说明书**（行政口吻那版）：怎么用、三种「关掉」的区别、窗口状态怎么看、出问题怎么自检、**它在本机保存了些什么**（exe / 配置 / 日志 / 自定义装饰图 / 开机自启那条注册表项）、**下载与安装说明**（本程序自己不下任何东西；模型由 Ollama 从官方库下载，附大小与存放位置）、怎么恢复默认和卸载。**不重复别的栏目**讲过的操作 |

### ④ 不想装 Python？打成单个 exe（自带解释器，双击即用）
```powershell
python "<项目目录>\desktop\tools\build_exe.py"      # 产物：desktop\dist\Easy Translator.exe
```
打包后的资源（默认装饰图、图标、README 头图）都塞在 exe 里，`ui.res_dir()` 会认 `sys._MEIPASS`；
配置和日志仍然落在 `%APPDATA%\EasyTranslator`。**开机自启**在 exe 里会自动写成「exe 自己 --daemon」，
并**同时放两处**：注册表 `HKCU\...\Run` + 「启动」文件夹（一个隐藏运行的 vbs）—— 有些机器的安全软件会把注册表那份清掉（本机实测 1~2 分钟内被删），两处只留哪份就用哪份。

- 改完**立即生效并自动保存**，不用重启；
- **顶部那颗大按钮就是总开关**：显示「翻译已开启 · 点此关闭」时点一下即关闭，
  显示「翻译已关闭 · 点此开启」时点一下即开启（顶部与底部状态同步显示「已启用 / 已暂停」）。
  关掉就是**完全不取词** —— 连鼠标轮询都停，也立刻写进配置文件，重启之后仍然保持关闭；
- **窗口右上角的「×」只是收起来**，取词继续在后台跑（再打开窗口就能看到开关状态）；
  要真正退出用**左栏底部**的「**退出桌面取词**」按钮。

### ④ 关闭

> **先分清两件事**：点窗口右上角的「**×**」只是**收起来**（取词继续在后台跑，
> 再双击桌面 App 就能把窗口叫回来）；下面的三种方式才是**真正退出进程**。

三种方式任选：

```powershell
powershell -ExecutionPolicy Bypass -File "<项目目录>\desktop\stop.ps1"   # 命令行（与 run.ps1 对称）
```

| 方式 | 操作 |
|---|---|
| **界面**（最简单） | 控制窗口**底部**的「**退出桌面取词**」按钮，点一下即退出整个进程 |
| **命令行** | `powershell -ExecutionPolicy Bypass -File "<项目目录>\desktop\stop.ps1"` |
| **任务管理器** | 结束 `python` 进程（或 `Stop-Process -Id <PID> -Force`） |

`stop.ps1` 会按 `python -m et_desktop` 找到进程 → 结束 → **二次确认无残留**后才报成功。

### ⑤ 再打开

重复 ② 即可（配置还在，不用重设）。装过桌面快捷方式的话，**双击那个图标**最快。

### ⑥ 桌面 App 与单实例

推荐给自己建一个**桌面快捷方式**（图标就是吉祥物），双击即弹出控制窗口：

| 快捷方式字段 | 值 |
|---|---|
| 目标 | `<项目目录>\desktop\.venv\Scripts\pythonw.exe` |
| 参数 | `-m et_desktop` |
| 起始位置 | `<项目目录>\desktop` |
| 图标 | `<项目目录>\assets\easy-translator.ico` |

（`pythonw.exe` 不带控制台窗口，所以双击不会闪黑框。）

图标不是手画的二进制：`python desktop/tools/make_app_icon.py` 生成 **「ET」艺术字（黑字白底）**
—— 白底圆角方片 + 极浅描边 + 居中的黑色 ET，一次打进 7 个尺寸（16/24/32/48/64/128/256）。
为什么改成字而不是立绘：16/32px 下图形会糊成一团，**字母反而一眼认得出来**；白色也是刻意的
（立绘是黑白墨线，透明底到深色任务栏/壁纸上会糊）。

```powershell
<python> desktop\tools\make_app_icon.py --style all      # 0 输出对照表：5 种艺术字风格 × 4 个尺寸
<python> desktop\tools\make_app_icon.py --style impact   # 换风格后重生成 .ico（默认 black）
```

窗口/任务栏图标也用同一枚 .ico（不用 Tk 的羽毛图标，也不挂到 pythonw 的图标上）。
换完图想确认「桌面 / 任务栏 / 标题栏」三处真的是同一枚：

```powershell
<python> desktop\tools\check_window_icon.py     # 把窗口图标像素抠出来跟 .ico 逐像素对拍
```

**单实例**：双击 App 时如果已经有一个在跑（常见的是开机自启的隐藏守护），
**不会**再起第二个监听进程 —— 新进程只写一个「请弹窗」标记
（`%APPDATA%\EasyTranslator\show.flag`），由在跑的那个把窗口弹到最前。
两份监听会变成「同一处弹两张卡片、UIA 轮询翻倍」，所以这条是硬保证。

**开关立刻生效**：按钮改写 `%APPDATA%\EasyTranslator\config.json` 的 `enabled`；
**外部**改这个文件（手改、脚本、`--settings` 窗口）也会在 1 秒内被热加载，不用重启。

鼠标停在任意英文单词上达到设定秒数即弹出气泡；移入气泡可钉住，点击复制该词，移开即收起。

## 取词是怎么做到的（优先级与产品铁律）

| 层级 | 手段 | 覆盖 |
|---|---|---|
| ① | **UIA**（Windows 辅助功能 `TextPattern.RangeFromPoint` + `ExpandToEnclosingUnit(Word)`） | 浏览器、记事本、Office、Electron 系（VS Code / 微信 / Discord）等绝大多数应用 |
| ② | **辅助功能说「光标下是中文」→ 就此静默** | 中文上**绝不弹窗**（产品铁律，E2E 钉住） |
| ③ | **视觉模型 OCR 兜底**（本地 Ollama 之类） | 图片、游戏、自绘 UI，以及辅助功能坐标映射不可信的地方 |

三层之间的判定细则（都是实测踩出来的）：

- **点空白不翻译**：`RangeFromPoint` 会把落点「扩展」成邻近的词，所以要用 `GetBoundingRectangles()`
  校验**词矩形确实包含光标**；只有紧贴的词缝空白（≤24px）才算「空白」，其余一律视为「这段文字不在光标底下」。
- **映射不可信 → 转 OCR**：PDF 阅读器、Electron 画布这类带缩放/虚拟化的控件，给出的文字坐标可能整体
  偏移几百像素（实测 370px），于是出现「指 A 处却翻译 B 处」。这种情况交给 OCR 按像素读；取不到矩形时同样转 OCR。
- **光标下是中文 → 静默，不走 OCR**：辅助功能说是中文就信它，绝不因为截图块里混着英文而误弹。
- **OCR 前先做墨迹判定**：只看光标正下方 ±12×±14 像素内有没有笔迹（150% 缩放下约半个字符宽），
  **纯空白直接判空、不调用模型** —— 既省下 1–2 秒，也杜绝小模型在空白处「凭空读出一个字母」。
  同时卡形状：细而长且横贯/纵贯窗口的（边框、表格线）、包围盒超过 44px 的（色块、图片）一律判空。
- **裁剪按「词」而不是按固定尺寸**：先量光标那一行的墨迹带，再沿该行向左右扩展出**光标所在的
  整个墨迹段（一个词）**；段太窄（≈一个字母）时至少给 3×字高的视野，红圈画在光标的真实位置 ——
  固定宽度会把 `Fraction`、`Exponent` 这类长词从中间切断，实测只剩 `frac`、`n`、`x` 这种碎片
  （用户报的「公式里翻译不了」「整词只识别一个字母」都是它）。拿不准时退化为 140×56。
- **识别结果还要过取词闸门**：英文词（≥2 字母）/ 希腊字母 / 花体·双线体等数学变体才弹；
  **单个普通英文字母、中文、数字、标点、`null` 一律静默** —— 图片里单字母遍地都是，而且
  「整词被裁成一个字母」的碎片会冒充它，误弹远多于收益（用户要求直接关掉）。
- **不动才翻译**：驻留计时从「光标停稳」那一刻起算，移动超过阈值（按 DPI 缩放）就重新计时。

## 引擎

按顺序来，前面的命中就不往下走：

- **内置表**（离线秒出，不联网也不推理）：
  - 希腊字母（读音 + 论文常见含义）、花体/双线体/哥特体等数学变体、孤立单字母变量 —— `et_desktop/mathsymbols.py`
  - **特称表**：IEEE、IBM、ACM 这类机构缩写，NeurIPS/CVPR/TPAMI 等会议期刊，NVIDIA/PyTorch 等公司框架，
    以及 CV、SEI、ELBO、XRD 等领域专名 —— `et_desktop/terms.py`
    （全大写缩写**只在原文也全大写时**才命中，避免 `it`→IT、`cv`→CV 误伤；跨领域含义不同的并列写进卡片，
    如 CV＝计算机视觉／循环伏安法、VC＝碳酸亚乙烯酯／风险投资）
- **有道公开词典**（默认，免 key，一次拿全音标/词性/例句/词形）
- **本地小模型**（任何 OpenAI 兼容端点，默认 Ollama `http://127.0.0.1:11434/v1` + `qwen2.5:1.5b`）——
  遇到全大写缩写会自动要求模型先给英文全称、再给中文译名与所属领域
- 视觉兜底默认 `qwen2.5vl:3b`（可关）

配置存 `%APPDATA%\EasyTranslator\config.json`，字段名与扩展的 `lib/settings-core.js` 一致
（`dwellMs`、`examplesCount`、`model.*`、`imageOcr.*`）；老配置的 `dwell`/`showExamples`
读到会自动迁移（秒 → 毫秒）。`tests/test_settings.py` 拿 JS 侧逐键比对防漂移。

## 测试

```powershell
cd desktop
python -m pytest tests\ -q       # 全量单测（英文判定 / 取词边界 / 归一化 / 特称表 / 配置）
python tests\test_lookup.py      # 同上，也可单跑某一个文件
python tests\test_terms.py       # 特称表：命中规则、大小写保护、表完整性
python tests\test_parity.py      # 与浏览器扩展 lib/normalize.js 逐字段同构性（防两边跑偏）
python -m et_desktop --selftest  # 渲染 + 取词 + 引擎连通
python tools\e2e_desktop.py      # 真机 E2E：起真实 Notepad → 悬停 → 断言（10 项）
```

`test_terms.py` 里有一条值得单说：**每个键都必须能通过 `is_english_word`**——
过不了的（如 `TNNLS`、`HTTPS` 这种字母多却无元音的）鼠标悬停根本取不到，键写了也白写，
这条测试就是防我再往表里塞无效键。

`test_parity.py` 值得单说：它用 node 跑**浏览器扩展那份 `lib/normalize.js`**，
把输出与 Python 实现逐字段比对。桌面端不是重写一遍逻辑，而是**同一份契约的第二实现**，
任何一边改了口径，这条测试立刻变红。

## 已知边界

- UIA 取词依赖应用提供 `TextPattern`；少数自绘 UI（老式 Java 程序、部分游戏）拿不到 → 交给 OCR 兜底
- OCR 兜底需要本地视觉模型在跑；没有就**静默**（不猜、不硬凑）
- 高 DPI 下已做感知（渲染随 DPI 缩放）；多显示器以物理坐标为准

## 隐私

与浏览器扩展一致：不收集、不上传任何数据。查词默认经由**有道公开词典**（被查的单词会发送至该服务）；
在「本地小模型」中启用本机模型后，可全程不出本机。截图只在 OCR 兜底时截取光标附近一小块、
**只发给你配置的那个端点**，不落盘（除非手动打开排障开关 `ocr_dump.on`）。

排障用的轨迹文件（源码模式在 `desktop/lookup_trace.log`，打包版在 `%APPDATA%\EasyTranslator\lookup_trace.log`）
只在本机记录**光标坐标与识别结果**（每个新位置一行，超过 256KB 自动清空），不上传、可随时删除。
